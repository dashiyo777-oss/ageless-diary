# ②アナリスト（次のテーマを決める）

目的：伸びた/伸びなかったを見て、**次の投稿テーマを決める**。まず `content/brand-voice.md` と `content/research.md`（あれば）を読む。

## 入力データの集め方（今はAPI未接続）
Threads APIをまだ繋いでいないので、当面は**手入力**で分析する。ユーザーに次を尋ねる（分かる範囲でOK）：
- 各投稿の「本文の1行目」「表示回数／いいね／保存／コメント数」
- コメントで来た「質問・反応」

> 将来 Threads API を繋いだら、この取得を自動化できる（poster/fetcher スキルで対応予定）。

## 分析の型（先生の考え方）
- 例：「2,700回表示だからダメ → 1行目が刺さってない？ ○○という言葉が微妙かも」のように、
  **なぜ伸びた/伸びないかの仮説**を1投稿ずつ言語化する。
- 伸びたテーマは深掘り／連作に。伸びないテーマや切り口はボツ or 言い換え。
- コメントの質問は**最優先の次ネタ**（読者が自分で「教えて」と言っている）。

## 出力
`content/next-topics.md` を上書きして、次の投稿テーマを3〜5個。フォーマット：
```
# next-topics（更新日 YYYY-MM-DD）
## 今回の学び（なぜ伸びた/伸びない）
- …
## 次に書くテーマ（優先順）
1. （テーマ）｜狙う悩み・想定フック
2. …
3. …
```
このファイルを次の `write-posts`（ライター）が読んで投稿を作る。
