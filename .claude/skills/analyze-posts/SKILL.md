# ②アナリスト（次のテーマを決める）

目的：伸びた/伸びなかったを見て、**次の投稿テーマを決める**。まず `content/brand-voice.md` と `content/research.md`（あれば）を読む。

## 入力データの集め方（今はAPI未接続）
Threads APIをまだ繋いでいないので、当面は**手入力**で分析する。ユーザーに次を尋ねる（分かる範囲でOK）：
- 各投稿の「本文の1行目」「表示回数／いいね／保存／コメント数」
- コメントで来た「質問・反応」

> 将来 Threads API を繋いだら、この取得を自動化できる（poster/fetcher スキルで対応予定）。

## 分析してほしいこと（先生の型）
1. 一番伸びた投稿と一番伸びなかった投稿を特定する。
2. 伸びた投稿の「1行目」「構造」「テーマ」の**共通点を3つ**挙げる。
3. 伸びなかった投稿の原因を、次の**5観点**で分析する：
   - 1行目が弱い（具体性がない／意外性がない）
   - 中身がスカスカ（数字・固有名詞・体験が入ってない）
   - AI感が出てる（「〜と言えるでしょう」等の不自然な表現）
   - 展開が薄い（1行目は良いのに中身が期待はずれ）
   - 外部要因（投稿時間が悪い等）
4. 伸びなかった投稿の「1行目」を、伸びた投稿の構造を参考に**書き直す**。
5. 次に書くべきテーマを**3つ提案**（理由つき）。
6. コメントの「質問」は**最優先の次ネタ**（読者が自分で「教えて」と言っている）。

## 注意（先生のルール）
- 「もっと具体的に」のような**抽象的アドバイスは禁止**。
- 必ず「**この文 → こう変える**」の形で書き換え案を出す。
- **数字で比較**する（表示回数・いいね・保存数）。

## 出力（2ファイル）
先生の設計どおり、2つに保存する。
1. `content/analysis-latest.md` に分析結果を上書き（上の1〜4の内容＝共通点・5観点・書き換え案）。
2. `content/next-topics.md` に「次に書くテーマ3つ」を上書き。**テーマだけでなく「どんな切り口で書くか」「1行目の案」もセット**で書く（次のライターがそのまま使える形）。フォーマット：
```
# next-topics（更新日 YYYY-MM-DD）
## 今回の学び（なぜ伸びた/伸びない）
- …
## 次に書くテーマ（優先順・切り口・1行目案つき）
1. （テーマ）｜切り口：…｜1行目案：「…」
2. …
3. …
```
このファイルを次の `write-posts`（ライター）が読んで投稿を作る。
