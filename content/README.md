# 半自動運用ワークフロー（先生の設計図を、安全な形で実装）

先生の「6エージェント」を、このリポジトリの**スキル**と**ファイル連携**で再現しています。
ファイルを介してAI同士がつながる仕組みです。

```
①research-threads → content/research.md
②analyze-posts    → content/next-topics.md
③write-posts      → content/post-queue.md
（④poster / ⑤fetcher / ⑥supervisor は下記ロードマップ参照）
```

## 使い方（Claude Codeで）
1. `/research-threads` … 伸びてるネタ・型・知識を集める
2. `/analyze-posts` … 反応を振り返り、次のテーマを決める
3. `/write-posts` … 投稿ドラフトを7本つくる（→ post-queue.md）
4. post-queue.md から**毎日1本コピペ投稿**。投稿したら `[ ]`→`[x]` に。
   - 記事があるテーマは、投稿直後に「リプ欄」テキストを自分への返信に貼る（本文には貼らない）。

> 週1回、上の①〜③をまとめて回せば1週間分のネタが貯まります。
> （すでに「週次ドラフト自動お届け」のRoutineも別途設定済み）

## いま安全に動かせるのは ①〜③（API不要・凍結リスクなし）
「調べる・分析する・書く」までは自動化してOK。**実際の投稿は当面"人が確認して手動"**。
これが70歳スタート・凍結を避けたい段階の現実解です（brand-voice.md の倫理とも一致）。

## ロードマップ（あとで／慎重に）
- **④poster（Threads API 自動投稿）**：先生も「大量投稿で凍結」と警告。導入時は必須の安全策：
  - 投稿前の**二重チェック**（人 or 別スキルで最終確認）
  - `post-history.md` に投稿日時・IDを記録
  - **レート制限**（1日◯本まで／連投しない）
  - まずは「下書きを作るだけ」で運用し、慣れてから投稿を繋ぐ
- **⑤fetcher（結果回収）**：投稿の24時間後に いいね/保存/コメントを取得。コメントの"質問"を next-topics へ。
- **⑥supervisor（監視）**：各ファイルの状態を点検し、ネタ切れ/投稿停止/データ欠落を検知して知らせる。

※ ④⑤は Threads API のアクセストークン設定が必要（先生の資料の「プレゼント（API連携）」参照）。
  準備できたら、安全策込みで一緒に実装します。
