## 0. このセミナー後半で一番言いたいこと（結論）

覚えて帰るのは2つだけ、と講師が明言：

1. **AGENTS.md を作る**（＝AIに毎回読ませる共通のルール表）
2. **修正したら、その理由をルールに1行足す**（＝ナレッジを育てる）

> 「これをやらないと、いつまで経っても自動化できないし、自動化してもいいものはできない」

そして大原則：**AIの出力は70点。100点にするのは自分。**

## 1. プロンプトより「ナレッジ」

- 今は1回の指示（プロンプト）で出させるより、**AIに"自分専用の資料"を持たせる（ナレッジ）**方が大事。
- なぜAIの出力をそのまま使えないか → **AIは「スレッズで何が伸びるか」を誰にも教わっていない**から。ネットの一般論は知っていても、伸ばし方の細かい基準は知らない。
- たとえ話：**入ったばかりの部下に、何も渡さず「いい感じの資料作っといて」**と言うのと同じ。当たり障りのないものしか出てこない。マニュアル（ナレッジ）を渡せば**70点**は出る。残り30点は人間の仕事。
- だから **やることは2つ、順番も大事**：
  1. **伸びる条件を知る**（＝No.16の内容。人間が理解していないとAIの出力を直せない）
  2. **その条件をAIに入れて揃える**
- ①を飛ばして②だけやると「AIの出力を毎回イチから直す作業」から抜けられない。

## 3. ナレッジの入れ方

### ナレッジ ＝ AIに渡す、自分専用の資料

スレッズなら**入れるもの7つ**：

| # | 入れるもの | 用意の仕方 |
|---|---|---|
| ① | 書き方のルール | Notion（テンプレ）コピーで今日そろう |
| ② | 投稿の型 9つ | 同上 |
| ③ | 1行目のフック集 | 同上 |
| ④ | 自分のジャンルの知識 | 毎日たまっていく |
| ⑤ | 伸びた投稿（自分・他人） | 〃 |
| ⑥ | もらったFB・グルコンの文字起こし | 〃 |
| ⑦ | 自分が出した投稿と、その結果 | 〃 |

- **①〜③はコピーすれば今日そろう。④〜⑦は毎日たまっていく。**
- 集め方：「**役に立ちそう**」くらいで、とりあえず保存する。継続で差がつく。自分宛でなくても、他の人がもらったFBも保存していい。**毎日10分・5個ブックマーク**が目安。SNSは24時間以内のものしか流れてこないので「1週間分まとめて」はAIでは難しい＝毎日やることが大事。

### AGENTS.md ＝「作業部屋の壁に貼ったルール表」

- AIに毎回必ず読ませる**共通の説明書**（守るルール＋読む資料の場所）。
- **CodexとClaude Codeで、同じAGENTS.mdを使える**（スライド：Claude Code は v2.1.277 以降で対応。既存の CLAUDE.md がある場合は `/config` の Project instructions で読み方を確認）。
- 以前は Claude＝CLAUDE.md、ChatGPT/Codex＝AGENTS.md と**別々に2個**作る必要があった → 今は**AGENTS.md 1個**で共通化でき、手間が半減。

### フォルダ ＝ 作業部屋（媒体ごとに分ける）

- YouTube／note／Threads／Instagram のように媒体ごとに部屋を分ける。「会社のデスクと同じで、座ったら資料がそろっている」状態にする。

### 入れるときに言うのは3つ

**①どんな情報を ②どこに ③どんな形で**。AIに整理まで作らせられる。

> 例：「（内容を貼って）上はThreads投稿の書き方のルールです。**ThreadsフォルダのAGENTS.mdに、見出しをつけて箇条書きで整理して**保存してください」

### 文字起こしを入れるとき

- 素材フォルダに「**4月9日_グルコン**」のような**日付＋内容の名前**で保存。抜け漏れなく。
- 音声の文字起こしは誤字が多い → 「**誤字を直して、何を直したか教えて**」と指示。
- 長いと途中で止まる → **30分ずつ区切る**。
- Loomの文字起こしはコピー可（3時間で約8〜9万文字）。YouTubeは字幕を自分でコピペするのが速い（専用拡張も可）。

### 伸びた投稿を集める

- **X・YouTube・TikTok からも**取る（10万表示以上、最低5万が目安）。保存時は「**なぜ伸びたか**」も一緒にメモ。
- 自動リサーチは**リサーチ用アカウント**で（本アカウントで自動操作すると凍結のおそれ）。

## 4. ナレッジの整理の仕方（後半のヤマ）

### 散らかると何が起きる

1. **AIが探すために大量に読む → 使える量（トークン）がすぐ上限に**
2. 同じ話が2か所 → AIが古い方を読んで作ってしまう
3. 自分でも、どこに何があるか分からない

> 「使っててすぐ上限が来る」＝ナレッジが多すぎ・整理されていないサイン。

### 整理のルール 5つ

1. **毎回読む「ルール表（＝AGENTS.md）」**と、**必要なときに読む「資料（＝ナレッジ）」**を分ける
2. **1テーマ1ファイル**。名前で中身が分かるように
3. 同じ話は**1か所だけ**に書く
4. **生の素材**と、そこから**抜き出したルール**を分ける
5. 作るときは、**読むファイルを指名する**

### フォルダの見本（具体形）

```
Threads/
├─ AGENTS.md        … 毎回読むルール表
├─ 投稿の型.md       … 9つの型
├─ 1行目フック集.md
├─ ジャンル知識/     … 自分のジャンルの中身
├─ 伸びた投稿/       … 投稿と、伸びた理由
├─ 素材/            … 文字起こし・FB
└─ 投稿ログ/         … 投稿と表示・いいね・フォロー
```

### AGENTS.md に書くこと（0〜7）

- **0 前提**：誰に向けたアカウントか／何で稼ぐか／自分の権威（検性）← **これが無いと「誰向けか分からない投稿」になる**
- 1 1行目のルール
- 2 本文のルール
- 3 終わり方とコメント欄
- 4 使う型（「投稿の型.md」から選ぶ）
- 5 文体（語尾・使わない言葉）
- 6 出し方（本文とコメント欄を両方出す／1回に何案）
- 7 出す前のチェック

※AGENTS.md本体には**基本ルールと「参照先（どこを見るか）」だけ**を短く書き、詳しい事例・素材は別ファイルに置く（間の"指示書"に徹する）。

### 「整理もAIにやらせる」

> 「素材フォルダの中で、同じ内容が2か所以上に書かれていないか確認して。重なっている所は1つにまとめて、どこをまとめたか教えて」

要否の最終判断は自分（壁打ちしながら）。

### 細切れにしすぎない

- ここでいう「分けすぎ」は**ファイルの"中身"**のこと。例：「1行目の書き方」はルールと良い例を**一緒に**置く。「本文」「コメント欄」など**別テーマは分けてよい**。
- **1テーマを、必要な前提や例まで分かる単位でまとめる**。フォルダ・ファイル数を減らす意味ではない。バラバラにすると、読む資料によって必要な情報が欠ける。長くなった資料は見出し・小テーマで分ける。

### 長さの目安はファイルの役割で違う

- AGENTS.md ＝ 基本ルール＋参照先を短く。詳しい事例・素材は別ファイル。
- スライド補足：Codexが起動時に読む指示の合計は**既定で32KiB＝日本語中心なら約1万文字が目安**（内容次第）。超えた部分は起動時の読み込みに入らない。

### ルールは短く、詳しい資料は必要なときに読む

作業時に**ファイル名と見出しを指定**して参照箇所を確認させる。

> 指示例：「本文の書き方.md の『具体例』まで読んで作って。**参照した見出しと、未読の部分があれば教えて**」

## 5. ナレッジを育てる（PDCA）

```
① 作らせる → ② 直す → ③ 直した理由をルールに1行足す → ①へ戻る
```

- こうすると**同じ指摘を2回しなくてよくなる**（＝一度注意されたことを繰り返さない部下）。
- ③を省略すると、AIはまた同じミスをする。
- **結果もナレッジにする**：伸びた投稿→「伸びた投稿」に保存して型にする／伸びなかった投稿→なぜかを1行。
- ただし、AGENTS.mdに書いても守られないことはある → **出すかどうか最後に決めるのは人間**。

## 6. 保存場所・その他

- 保存先はどこでもよい。講師は **Obsidian**（著者用）＋ **Notion**（共有用）。クラウド同期（iCloud等）で**複数端末から同じものを見られる**ようにするのがコツ（完全ローカルだと共有しづらい）。
- 今回の内容は**「フォロワーを伸ばすバズ投稿を作る」話**。**マネタイズはベクトルが別**（コンセプト勝負）。アフィリなら投稿の質＋仕組みで応用余地あり、という位置づけ。

## 7. よしだ的・honest評価（◎△×）

### ◎ 採用（そのまま効く）
- **これはよしだの現運用そのもの**。ageless-diary の `knowledge-*.md`／`knowledge-INDEX.md`／`post-queue.md`／`CLAUDE.md` は、まさにこのセミナーの「ナレッジ＋ルール表」システム。No.16（投稿設計）の**続編＝運用編**として完全に噛み合う。
- **整理のルール5つ**（1テーマ1ファイル／同じ話は1か所／生素材とルールを分ける／読むファイルを指名）は、肥大化した `post-queue.md`（約68KB）や knowledge群の整理に直接使える。
- **結果もナレッジ**＝インサイト（ビュー数）を「伸びた投稿／伸びた理由」として貯める運用は、既にやっている分析（案54=9610、頭皮3086 等）と一致。型に落とす価値が高い。
- **PDCA（直した理由をルールに1行）**＝これまでの「教訓①〜⑲」の積み上げそのもの。継続。

### △ 一部だけ採用
- **「AGENTS.mdに統一」**：よしだの環境は Claude Code（my-portofolio に CLAUDE.md）で既に機能しているので、**無理に改名しない**。必要になれば検討する程度でよい。仕組みの考え方（毎回読むルール表＋別置きの資料）だけ借りる。
- **煽り系の1行目例**（No.16と共通：「炎上覚悟」「アマニ油ヤバい」等）は、よしだの穏やかなトーン＆薬機法に合わない → **技法だけ**取り、断定・煽りは使わない。

### × 採用しない
- **「バズ投稿の丸パクリ収集」「AI自動リサーチで量産」**：よしだの強みは**70歳の実体験**。他人のバズは"言い回し・構成の参考メモ"に留め、中身は必ず自分の体験に置換する（**教訓④＝作り話をしない**を厳守）。
- **フォロワー数至上のバズ狙い**：正直軸（弱み・失敗の告白）で伸びているのが実データ。無理なバズ化はしない。
